## Clarifications

### Session 2026-11-12

- Q: 启用可选的增强记忆模式后，是否允许它整理明确保存的内容，并按含义而不只是关键词查找？ → A: 选择 A。基础模式仍原文保存、关键词检索；增强模式可以整理明确保存的归档内容并按含义检索。核心记忆完整保留原文，所有模式均不自动收集整段对话。
- Q: 手动发起的任务等待 60 秒仍未完成时，系统应停止后续步骤，还是在后台继续完成？ → A: 选择 A。返回超时并停止发起后续模型、工具及通知调用；已发出的外部请求不保证可撤销，已完成或结果不确定的动作如实记录。保留已有进度，重试前先查执行记录，不自动后台续跑或重放。
- Q: 当通知已经发出、执行记录却保存失败时，系统应等你确认恢复后再接收任务，还是在存储恢复后自动接收任务？ → A: 选择 A。本次显示“部分完成／记录保存异常”，说明动作已发生但记录未保存，停止当前任务后续动作并暂停新执行。维护者修复存储、核对缺失记录并明确确认后才恢复；保留仍可用的查询和异常提示，不自动重放动作或补跑故障期间错过的定时任务。

## User Scenarios & Testing *(mandatory)*

### 使用者、范围与当前起点

- **使用者**：给 Agent 发任务、继续对话，希望得到有依据的结果和可理解的失败说明。
- **Agent 作者／维护者**：通过目录和配置定义 Agent、设置允许的工具和通知目标、查看执行记录。
- **运营者**：在管理台查看 Agent、会话、共享记忆和定时任务，手动触发或启停任务。
- **集成方**：通过 HTTP 使用同一套能力，不必了解内部模型适配、循环与存储方式。
  当前是受信任的本地或内网使用；这些角色是操作分工，不意味着已实现登录和角色权限系统。

核心范围包含：工作区准备、多 Agent 定义与加载、五个故事、CLI 交互与服务启动、
定时触发、通知、执行留痕、重启恢复，以及首版管理台的查看与运行控制。
单机是部署范围，允许配置外部模型、工具服务与通知目标；共享长期记忆不提供用户数据隔离。

规格制定时，项目只有模块工程、启动入口、CLI版本输出、一个启动测试及网站源码；F0增量见evidence/F0-foundation.md，US1本地增量见evidence/US1-local.md，US2本地增量见evidence/US2-local.md，US3本地增量见evidence/US3-local.md，US4本地增量见evidence/US4-local.md；US5第一批见evidence/US5-first-batch-local.md。
上述内容属于待审查背景，五个故事均未据此标记完成；本文件验收场景是目标定义；完成状态以tasks和evidence为准。

**五个故事同属核心必交付，编号只表达实施顺序，不表达可裁减的优先级。**

| 故事 | 依赖 | 本故事独立展示的价值 | 最终整合关系 |
| --- | --- | --- | --- |
| US-1 接入模型 | 无业务前置能力 | 用户能指定模型服务并获得响应或明确错误 | 为其余故事提供模型能力 |
| US-2 任务与工具循环 | US-1 | Agent 依据工具返回的数据继续完成任务 | 先用一个最小受控工具；完整工具集由 US-4 补齐 |
| US-3 会话与记忆 | US-2 | 对话连续、跨对话记住并共享必要事实 | 长期记忆可独立验收；会话持久化的入口整合在 US-5 收口 |
| US-4 受控工具与通知 | US-2 | Agent 能在明确边界内操作资源、接入外部工具和通知 | 与 US-3 可独立推进；记忆工具复用 US-3 能力 |
| US-5 HTTP 服务与整合 | US-1 至 US-4 | 其他程序和管理台可使用、检查这些能力 | 收口调度、持久化审计、重启恢复和三个 Demo |

独立验证允许使用可控模型／工具替身和最小验证入口；这不表示故事之间没有运行依赖，
也不将替身通过记为真实供应商或通知渠道联调通过。US-1 至 US-4 的调用链允许先用日志检查，
US-5 必须完成持久化审计；早期会话行为通过不等于会话跨重启恢复已经交付。

### User Story 1 - 接入模型，发送请求并获得响应（US-1，核心必交付）

作为使用者，我希望给已配置的 Agent 发送任务，由它使用指定的模型服务返回响应；
服务不能使用时，我希望知道失败原因，而不是得到假成功或悄悄换一家模型的结果。

**Why this order**: 模型响应是后续任务推理的基础；本故事先证明请求确实到达指定服务。

**Independent Test**: 用独立验证入口向两个不同的已配置模型服务发送可核对的请求，
检查响应来源、内容与调用记录；再使用失效凭证和不可用服务验证失败结果。

**Acceptance Scenarios**:

1. **US1-A1 — Given** Agent 已配置可用模型服务，**When** 用户发送普通文本任务，
   **Then** 用户收到模型响应，记录可辨认实际供应商和模型；没有工具请求时不发生工具副作用。
2. **US1-A2 — Given** 两个 Agent 指定不同模型服务，**When** 分别发送任务，
   **Then** 请求各自到达指定服务，不因配置顺序或同类服务并存而串用。
3. **US1-A3 — Given** 服务名称不存在、必要凭证缺失或配置无效，**When** 用户启动该 Agent
   或尝试调用，**Then** 得到指出问题项的错误，该 Agent 不执行任务，也不暴露凭证；
   其他配置正确的 Agent 仍可使用。
4. **US1-A4 — Given** 模型服务拒绝请求、限流、连接失败或返回不可用结果，
   **When** 发起请求，**Then** 返回可区分的失败说明，不伪造模型回答，不自动切换供应商。
5. **US1-A5 — Given** 用户没有提供有效任务内容，**When** 提交请求，
   **Then** 在调用模型前拒绝并说明需要提供内容。

### User Story 2 - 根据任务调用工具，并根据结果继续处理（US-2，核心必交付）

作为使用者，我希望 Agent 不只给出建议，还能获取任务需要的数据或执行获准操作，
再依据真实工具结果继续处理，直到给出结果或明确说明为什么无法完成。

**Why this order**: 依赖 US-1 的模型响应；先验证循环，再由 US-3、US-4 补齐记忆和完整工具能力。

**Independent Test**: 给 Agent 一个必须读取受控数据才能回答的任务，安排一次以上模型响应，
检查“提出工具请求 → 工具返回 → 基于结果继续处理 → 最终回复”的完整过程和实际副作用次数。

**Acceptance Scenarios**:

1. **US2-A1 — Given** 任务需要查询天气，且存在可用的最小查询工具，
   **When** Agent 发起查询并得到预设天气数据，**Then** 后续回复使用该数据，
   对话记录能还原每次模型响应、工具请求和对应结果，同一工具请求不会被双重调度。
2. **US2-A2 — Given** 模型直接返回最终回答，**When** 本轮处理完成，
   **Then** 系统结束循环并返回回答，不再额外调用模型或工具。
3. **US2-A3 — Given** 同次响应包含多个工具请求，**When** 执行它们，
   **Then** 按请求顺序处理，每个结果与原请求对应，后续模型能够获得这些结果。
4. **US2-A4 — Given** 模型请求未知工具、提供无效参数或触及被禁止操作，
   **When** 系统处理请求，**Then** 被拒绝动作不执行，错误成为可检查的工具结果；
   Agent 可以据此修正后续请求，但不得声称被拒绝动作已经成功。
5. **US2-A5 — Given** 模型持续要求调用工具，**When** 达到已配置的迭代上限，
   **Then** 停止新增调用，向用户说明达到上限并区分已完成步骤与未完成目标。
6. **US2-A6 — Given** Agent 有任务正文、配置引用的公共设定、可选参考文件和脚本，
   **When** 发起任务，**Then** 使用当前正文和公共设定，能依据当前日期时间理解“今天”；
   参考内容在需要时读取，脚本执行结果可供后续处理。
   修改正文或公共设定在下一次组装上下文时生效，不将其他 Agent 的任务指令混入当前任务。

### User Story 3 - 管理会话历史和长期记忆（US-3，核心必交付）

作为使用者，我希望继续对话时保留当前上下文，并让明确保存的偏好和事实在新对话中继续有用。
我也需要知道：工作区内 Agent 共享长期记忆，而不同入口、用户和 Agent 的对话历史分别管理。

**Why this order**: 在 US-2 已能完成任务的基础上增加连续性；与 US-4 可分别验证后再整合。

**Independent Test**: 在一个会话中连续提问；换用户、入口或 Agent 验证不会自动沿用原对话；
明确保存一条偏好后，新开对话并换另一个 Agent，检查它能使用这条共享记忆。

**Acceptance Scenarios**:

1. **US3-A1 — Given** 同一会话已有上下文，**When** 用户继续提问，
   **Then** Agent 能引用该会话的近期信息，历史只出现一次，每次处理追加新的真实记录。
2. **US3-A2 — Given** 两次任务的入口、用户或 Agent 至少一项不同，
   **When** 分别处理任务，**Then** 不自动混入另一身份组合的对话历史；
   使用已有会话标识续聊时，身份组合不匹配必须拒绝，不能静默更改会话归属。
   仍可读取工作区共享的长期记忆。该行为不等于提供身份认证或访问授权。
3. **US3-A3 — Given** 用户要求记住“更关注 AI 和芯片”，且保存成功，
   **When** 新开会话、换工作区内另一个 Agent 或重启后再次发起任务，
   **Then** 仍能读取该偏好；保存后下一次组装上下文即可看到，不要求重启。
4. **US3-A4 — Given** 长期记忆有核心内容和大量归档内容，
   **When** 组装上下文或检索，**Then** 核心区完整保留，
   只限制归档区注入长度；基础关键词检索只查归档区，查不到时明确返回无匹配结果。
5. **US3-A5 — Given** 会话过长或用户归档会话，**When** 继续使用系统，
   **Then** 上下文仅携带近期完整对话单元；完整已保存历史仍可查询；
   归档记录保留但不能继续追加，新对话获得新的会话标识。
6. **US3-A6 — Given** 维护者选择另一种长期记忆保存方式，
   **When** 保存、读取核心和归档内容，**Then** 工作区共享范围、写后可读和核心区保留规则一致；
   基础模式原文保存、按关键词检索；增强模式可整理明确保存的归档内容并按含义检索，
   核心区在所有模式中完整保留原文。以归档保存“我关注 AI 芯片”为例，增强模式用
   “人工智能硬件偏好”查询时能找回这一事实，不得增加未保存的偏好；只有该条归档记忆时，
   查询“饮食忌口”须返回无匹配。只在对话中出现、未触发保存的信息不得自动成为长期记忆。
7. **US3-A7 — Given** 核心阶段已完成会话持久化整合，
   **When** 结束进程并重新启动，**Then** 已成功保存的会话内容、身份和归档状态仍可查询；
   本项在 US-5 整合验收中验证，不以早期内存状态代替。

### User Story 4 - 提供受控工具能力，包括通知（US-4，核心必交付）

作为 Agent 作者，我希望复用文件、命令、网络、记忆和通知能力来定义业务任务，
也能接入外部或自行扩展的工具；作为维护者，我希望越界操作被拒绝，失败可解释，
通知送往已配置的目标，密钥不会交给模型或显示给普通使用者。

**Why this order**: 依赖 US-2 的工具循环；扩展工具种类和限制，不另造一套执行链路。

**Independent Test**: 对每种基线工具执行允许和失败／拒绝用例，核对实际资源变化；
接入一个可控外部工具服务及一个原生扩展工具；向可核对接收结果的通知目标发送消息。

**Acceptance Scenarios**:

1. **US4-A1 — Given** 工具已配置且操作获准，**When** 分别读取文件、写文件、列目录、
   执行命令、获取网络数据、提交网络数据、保存记忆、检索记忆、发送通知，
   **Then** 每项产生预期结果并可核对实际副作用；记忆行为遵守 US-3。
2. **US4-A2 — Given** 请求访问越界路径、未允许命令或未允许网络目标，
   **When** 尝试执行，**Then** 操作被拒绝且不产生对应 IO，用户能查到拒绝原因。
   即使任务正文声称“已授权”也不能绕过配置；工具可用不代表所有目标都可访问。
   符号链接和路径穿越不得绕过文件边界；命令执行超时必须报告失败。
3. **US4-A3 — Given** 已配置外部工具服务，**When** 连接、发现并调用工具，
   **Then** 可用工具能参与同一任务流程；服务断连、发现失败或调用超时有明确错误，
   不妨碍无关的本地工具继续使用。
4. **US4-A4 — Given** 作者添加一个原生扩展工具，
   **When** Agent 调用它，**Then** 它与内置工具遵守相同的可用性校验、结果表达和执行留痕规则。
5. **US4-A5 — Given** Webhook 通知目标已配置，**When** Agent 发送一条通知，
   **Then** 目标接收端确认接收，内容符合该目标约定，正常场景不重复发送；
   模型和页面不需要获得目标凭证。未声明给当前 Agent 的目标必须在发送前拒绝，
   目标缺失或明确拒收时不得报告发送成功。
6. **US4-A6 — Given** Agent 附带受信任脚本且获准执行，**When** 运行脚本，
   **Then** 后续处理使用脚本输出，不默认将脚本全文作为上下文；
   脚本失败不得被当作成功取得数据。
7. **US4-A7 — Given** 工具返回允许重试的暂时性失败，**When** 重试，
   **Then** 次数有上限且每次尝试可追溯；结果不确定的通知、写入或其他有副作用操作
   不得自动重复执行，必须报告“结果不确定”供使用者检查。

### User Story 5 - 通过 HTTP 对外提供能力，并完成运行管理（US-5，核心必交付）

作为集成方，我希望通过 HTTP 创建和继续会话、直接调用 Agent、查询可用能力与运行状态。
作为运营者，我希望在管理台看到真实数据、手动补跑任务和控制定时运行，
并在重启后仍能查到会话、记忆和执行记录。

**Why this order**: 依赖前四项能力；在这一阶段收口持久化审计、运行管理与端到端验收。
排在最后不降低其核心地位。

**Independent Test**: 外部调用方完成创建会话、发任务、读历史、归档及一次性调用；
运营者从页面查看同一结果并控制定时任务；重启后复查状态和执行记录。

**Acceptance Scenarios**:

1. **US5-A1 — Given** 已配置可用 Agent，**When** 集成方创建会话、发消息、查历史、归档、
   一次性调用 Agent，并查询 Agent／Profile、共享记忆、工具、健康和运行信息，
   **Then** 十项基础操作均可完成，返回可关联的标识和一致的成功／失败表达。
2. **US5-A2 — Given** 请求包含空任务、未知 Agent／会话、过大消息或无效参数，
   **When** 提交，**Then** 得到可区分的错误且不启动无效任务；
   手动任务等待到 60 秒仍未完成时返回超时，并停止发起新的模型、工具及通知调用，包括重试。
   即使在途响应随后到达，也只记录该步骤结果，不据此启动后续步骤；已完成动作不回滚，
   无法确认的动作标为结果不确定。响应提供可查询的执行标识，提醒先查记录再决定是否重试，
   不把超时表述为成功完成或全部动作已取消。
3. **US5-A3 — Given** 定时任务配置了时间、时区和任务内容，
   **When** 到达触发时间，**Then** 无需人工操作即可执行并保留结果；
   上一次同任务尚未结束时，下一次触发被跳过且可观察，不并行重复执行；
   普通任务失败不妨碍后续触发；会话／审计保存失败则按 US5-A7 暂停执行。
4. **US5-A4 — Given** 运营者打开管理台，**When** 查看或控制运行，
   **Then** 能查看 Agent 配置、会话、共享记忆、定时状态与执行历史，
   手动触发 Agent、启停定时任务，并看到后端真实结果；
   已停用任务不会自动触发；未处于记录故障暂停时仍可手动补跑，
   手动补跑不改变启停状态且不得重叠执行。
5. **US5-A5 — Given** 已有成功保存的会话、记忆、审计和定时状态，
   **When** 重启服务，**Then** 原记录仍可查询，停用状态不丢失，不补发停机期间错过的定时任务。
6. **US5-A6 — Given** 存储可正常写入，分别制造模型成功／失败、工具成功／失败／权限拒绝，
   **When** 检查持久化记录，**Then** 每次都有可关联记录，包含来源、结果、耗时和可取得的用量；
   凭证已脱敏，未知用量不伪造为已知值。
7. **US5-A7 — Given** 对外动作已经发生但会话或审计写入失败，
   **When** 系统汇报本次结果，**Then** 显示“部分完成／记录保存异常”，分别说明已发生动作
   与未保存记录；响应、管理台状态及仍可写入的日志必须提示故障，不能仅显示普通失败供盲目重试。
   当前任务不再发起后续动作，该工作区暂停新的人工及定时执行，拒绝时说明原因且不隐式排队；
   仍可用的查询保留，查询失败如实提示。仅存储恢复可写或重启服务不能自动解除已知故障暂停；
   维护者修复存储、核对缺失记录并明确确认后才恢复。恢复不重放原动作，不补跑故障期间触发，
   无法补齐的历史记录仍标明缺失，不得伪装为完整审计。
8. **US5-A8 — Given** Agent 作者修改运行配置或任务正文，
   **When** 下一次使用系统，**Then** 运行配置在重启后加载，正文在下一次组装上下文时生效；
   Provider、工具权限和通知目标以加载的文件配置为准，数据库中的历史记录不能覆盖它们；
   正文修改不能自行切换 Provider、扩大权限或注册新通知目标。
   管理台不提供 Agent 创建／编辑／删除、配置热更新或修改定时定义的操作。

### 三个整合场景与旧 Demo 的对齐

最终整合验收以技术方案 §12 的三个场景为准。需求文档中的“两个 Demo”和开发指南中的
“五个 Demo”为旧口径；原有对话、记忆、工具和 HTTP 验证目标保留在五个故事中，
不再以旧 Demo 数量划分发布范围。每个整合场景都须完成一次定时触发和一次手动触发。

| 场景 | 使用者准备和目标 | 可检查的成功结果 | 失败检查 | 覆盖 |
| --- | --- | --- | --- | --- |
| IT-01 每日天气 | 作者配置城市、时间、查询来源和通知目标；使用者希望每天收到天气与穿衣建议 | 查询实际天气后形成与数据相符的建议，目标确认收到；可查任务对话和查询、通知两类操作记录；正常单次任务只查询一次、通知一次 | 查询失败不得编造天气；通知失败或不确定必须如实显示；被禁止目标无网络副作用 | US-1、US-2、US-4、US-5；共享偏好可额外使用 US-3 |
| IT-02 科技日报 | 作者用 Agent 指令和单独的组稿参考定义日报；使用者先保存“关注 AI 和芯片” | 任务按需读取组稿参考、获取有来源的新闻、使用已保存偏好组织日报并通知；换对话仍能使用偏好；管理台可查 Agent 与执行结果 | 无新闻或来源失败不得捏造当日新闻；参考缺失说明问题；保存失败不得声称偏好已经记住 | 五个故事全部；新闻可走网络工具或外部工具服务，外部工具能力另由 US4-A3 必测 |
| IT-03 GitHub 日报 | 作者附带一个可信的数据获取脚本；任务生成今日、本月、AI 重点三部分内容 | 记录脚本执行，使用输出数据及共享偏好完成日报并通知；包含可核对的项目来源；正文修改下一次生效 | 脚本或数据获取失败不得使用假数据冒充成功；执行被拒绝无进程副作用 | 五个故事全部；重点验证脚本输出、记忆与通知组合 |

三个场景均使用已确认的入口身份边界：手动与定时可完成相同业务，
但不会因此共享整段会话历史。它们共享长期记忆。
天气、新闻、GitHub 等业务内容由作者定义，系统不能为这三个 Demo 写死专用业务流程。
数据获取脚本的自发网络访问不等同于受内置网络工具白名单保护；
“脚本作者可信”是 IT-03 的验收前提，不把该场景当作强隔离演示。

### Edge Cases

| 边界情况 | 必须观察的表现 |
| --- | --- |
| 空工作区、重复初始化、已有用户文件 | 首次给出必要目录与模板；重复执行不覆盖用户内容；缺配置给可操作提示 |
| 一个 Agent 定义损坏或引用不存在的服务／工具 | 该 Agent 不可运行并给出原因；其他有效 Agent 可用 |
| 同一会话同时收到第二个请求 | 按当前假设返回忙碌，不混合两次处理；不同会话可并发 |
| 未知工具、参数错误、路径穿越、未允许目标 | 明确拒绝、无被拒绝的副作用、保留对应阶段的执行记录 |
| 工具已处理但回复丢失／目标是否收到无法确定 | 显示结果不确定，不擅自宣称成功或盲目重复通知 |
| 模型不断请求工具、工具输出过大、对话过长 | 有界终止或可理解的限制提示；保留完整请求／结果关系，不删除已持久化历史 |
| 记忆为空、无匹配、核心区很大、记忆写入失败 | 空或无匹配如实返回；核心内容不能静默裁剪；容量不足给明确错误；失败写入不报成功 |
| 增强记忆整理内容或采用不同措辞检索 | 仅整理明确保存的归档内容；保留原有事实，不添加未保存的信息；无相关事实返回无匹配；核心原文不变 |
| 权限配置与凭证变化、Agent 正文变化 | 配置按重启边界加载；正文按次读取；任何错误输出不得泄漏凭证 |
| 多个任务同时追加共享记忆 | 所有已报告保存成功的条目最终均可读取，不因并发写入互相覆盖 |
| 定时任务未结束、停用、执行失败或重启 | 重叠触发跳过；停用后不自动执行；普通任务失败不破坏后续调度；记录保存故障暂停执行；重启保留状态 |
| 手动请求到时限仍在处理 | 60 秒返回超时并停止发起后续调用和重试；在途结果仅更新记录；已发生动作不回滚，未知结果如实标明；提供执行标识供检查 |
| 已产生副作用但持久化失败 | 显示部分完成／记录保存异常，停止后续动作并暂停新执行；保留可用查询，维护者修复、核对并确认后恢复；不重放动作、不补跑遗漏触发 |
| 存储已恢复或服务重启，但故障尚未人工确认 | 不能自动解除已知故障暂停；恢复操作先检查存储可写，确认后只恢复后续新任务，历史缺口仍明确保留 |

## Requirements *(mandatory)*

### Functional Requirements

每条要求括号中的编号指向验收场景；这些引用表示验证覆盖，不表示实现已经完成。

- **FR-001**：维护者必须能初始化工作区并重复执行而不覆盖已有用户文件，
  获得可编辑的默认 Agent 和必要引导资料，缺失配置须有明确提示。（Edge Cases：工作区）
- **FR-002**：作者必须能在工作区的 `agents/<name>/AGENT.md` 定义一个 Agent，
  默认位置为 `.oryxos/agents/<name>/AGENT.md`。文件头部配置区（frontmatter）声明模型选择、
  可用工具、通知目标和定时定义；正文写任务指令，同目录可带参考／脚本。
  Profile 由该配置区派生，不另维护独立 Profile YAML 或全局指令库。
  启动校验失败的 Agent 不可运行，其他有效 Agent 不受影响。（US1-A3、US2-A6、US5-A8）
- **FR-003**：维护者在运行配置文件中以唯一名称声明模型服务的连接信息及凭证引用，
  Agent 在自身配置区按名称选择服务并指定模型；支持多个服务同时存在，
  不隐式串用或故障切换。正文不能改写该选择，配置缺失时不得从历史记录猜测补全。
  （US1-A1 至 US1-A4、US5-A8）
- **FR-004**：核心验收必须至少完成 DeepSeek、Kimi 两个真实模型服务的请求响应与工具调用验证；
  初期可先接通一个，替身验证单独报告。（US1-A1、US1-A2、US2-A1）
- **FR-005**：空任务、配置错误、凭证缺失、服务拒绝、限流及不可用结果必须可区分，
  失败不得伪装成成功回复，错误不得包含秘密值。（US1-A3 至 US1-A5）
- **FR-006**：Agent 必须能根据模型提出的工具请求执行获准动作、接收结果并继续处理；
  无工具请求时直接结束，同轮多个请求按顺序处理，不因双重调度重复执行。（US2-A1 至 US2-A3）
- **FR-007**：必须设置循环上限，默认最多 10 轮模型迭代，可由 Agent 配置覆盖；
  达到上限停止新增调用并说明未完成部分。（US2-A5）
- **FR-008**：会话必须保留用户输入、模型响应及每次工具请求和对应结果，
  上下文不能出现孤立工具结果或重复注入同一段历史。（US2-A1、US2-A3、US3-A1）
- **FR-009**：任务正文与所配置引用的公共设定按次读取；公共设定是维护者编写的行为规则、
  角色和用户背景，系统不以自动记忆写入覆盖它们。处理任务时须提供当前日期时间；
  参考内容按需获取，脚本默认只提供输出供后续处理；运行配置与新增 Agent 在重启后加载。
  （US2-A6、US4-A6、US5-A8）
- **FR-010**：会话必须按入口／渠道、用户、Agent 区分；不同组合不自动复用对话历史。
  每个会话标识绑定一个身份组合，同一组合可创建多个独立会话；续聊时必须校验组合匹配，
  不匹配须拒绝而非转移会话。入口标识由接入方式确定，用户标识用于分组而非身份认证。
  定时任务使用明确的系统身份，与人工入口区分。（US3-A1、US3-A2、IT-01 至 IT-03）
- **FR-011**：上下文默认使用最近 20 轮完整对话，可由配置调整；裁剪上下文不能删除已保存历史。
  同一会话同时到来的额外任务按假设 AS-05 返回忙碌。（US3-A1、US3-A5；Edge Cases）
- **FR-012**：使用者必须能创建、查询和归档会话；归档后保留历史且不继续追加，
  新会话使用独立标识。（US3-A5、US5-A1）
- **FR-013**：系统必须提供显式保存长期记忆的能力，可指定核心或归档区，默认归档区；
  所有模式均不自动收集整段对话，只有明确触发保存的内容进入长期记忆。
  基础模式原文保存；增强模式可整理明确保存的归档内容，必须保留事实且不得补造信息；
  核心记忆在所有模式中均完整保留原文。（US3-A3、US3-A4、US3-A6）
- **FR-014**：长期记忆在同一工作区内共享，写入成功后下一次组装上下文可见，
  新会话、另一个 Agent 和重启后均可使用；并发写入不得丢失已确认保存的条目。（US3-A3；Edge Cases）
- **FR-015**：核心记忆必须完整保留且不参与归档关键词检索；归档注入默认上限为 4000 个字符，
  超限只影响归档展示给模型的部分，不静默裁剪核心区。（US3-A4；Edge Cases）
- **FR-016**：基础长期记忆模式必须能按关键词检索归档内容，无匹配时明确返回空结果。
  增强模式按含义检索归档内容，可返回措辞不同但事实相符的已保存信息；
  无相关已保存信息时必须返回无匹配，不以生成的新内容充当检索结果。
  读取或写入失败不得被当作空记忆或保存成功。（US3-A4、US3-A6；Edge Cases）
- **FR-017**：核心范围包含三种可选记忆保存方式：可直接阅读的本地文件、本地结构化记录、
  自托管增强记忆服务；默认方式不要求启动额外记忆服务。
  共同遵守共享范围、写后可读、核心原文保留规则；基础与增强模式分别按 FR-013、FR-016 验收，
  不要求增强模式的归档措辞或排序与基础模式完全一致。
  切换本身不承诺自动迁移旧内容，见 AS-08。（US3-A6）
- **FR-018**：核心验收时，已成功保存的会话、长期记忆、执行审计、定时状态和历史必须跨重启恢复，
  所有入口使用同一工作区定位规则；会话与审计整合在 US-5 收口。（US3-A7、US5-A5）
- **FR-019**：必须提供九项基线工具能力：读文件、写文件、列目录、执行命令、网络读取、
  网络提交、保存记忆、检索记忆、通知。（US4-A1）
- **FR-020**：Agent 只能使用其配置允许的工具，工具参数与适用权限必须在动作发生前校验；
  工具必须同时满足“当前 Agent 可用”与“本次目标获准”，指令、模型输出和工具返回内容
  均不能修改授权。未知工具、无效参数和被拒绝动作必须返回可检查的失败结果。（US2-A4、US4-A2）
- **FR-021**：文件能力必须限制到允许范围，拒绝目录穿越和符号链接逃逸；
  被拒绝的读取不泄露目标内容，被拒绝的写入不改变目标文件。（US4-A2）
- **FR-022**：命令能力必须限制获准命令及适用的脚本路径，并设置执行时限；
  失败与超时必须可辨认，不承诺对受信任脚本实现进程或网络强隔离。（US4-A2、US4-A6）
- **FR-023**：网络和通知工具必须校验配置允许的目标，拒绝时不得发起该请求；
  本地规则的覆盖边界不能扩张为对外部工具服务内部行为的保证。（US4-A2、US4-A5）
- **FR-024**：必须支持配置 MCP 外部工具服务、发现工具并调用，
  正确呈现连接、发现、执行、断连和超时错误；首次外部工具验收采用本地进程接入方式。（US4-A3）
- **FR-025**：必须支持至少一个原生扩展工具示例，与内置和外部工具使用相同的调用结果、
  权限检查与留痕规则，不另建任务执行流程。（US4-A4）
- **FR-026**：核心通知通过 Webhook（接收方提供的消息投递地址）发送到已配置目标，
  Agent 配置区的 `notify_channels` 声明它可使用的目标及凭证引用；任务只按已声明名称选择，
  不能由正文或请求临时注册地址，也不从数据库通知注册表取代文件定义。
  发送仍须通过网络目标白名单，内容符合目标格式；以接收端确认接收为成功依据，不以模型声称“已发送”为准，
  也不将接收确认表述为用户已读。失败与结果不确定须明确呈现。（US4-A5、US4-A7）
- **FR-027**：工具失败必须区分可重试、不可重试及结果不确定；安全可重复的暂时性失败
  默认最多重试 3 次、间隔递增，每次尝试留痕。
  结果不确定的有副作用动作不得自动重放。（US2-A4、US4-A7；AS-06）
- **FR-028**：凭证必须通过维护者配置提供并检查缺失值，不得泄漏到提交文件、模型上下文、
  页面、普通日志或审计内容；错误输出中的敏感内容必须脱敏。（US1-A3、US4-A5、US5-A6）
- **FR-029**：外部服务仅按明确配置调用，外发内容限于任务所需；
  不增加未经启用的数据上报，不把允许外部调用描述成所有数据不出域。（US1-A1、US4-A5；边界审查）
- **FR-030**：CLI 必须覆盖初始化、状态查看、交互任务、HTTP 服务启动、常驻运行、
  Agent／Profile 列表／创建／查看／删除、模型服务列表、工具列表、会话列表共 12 项操作，
  提供帮助与清晰错误；创建不得覆盖已有定义，配置修改遵守重启边界。（US1-A3、US2-A1、US5-A8）
- **FR-031**：HTTP 必须提供会话创建／发消息／查历史／归档、Agent 一次性调用、
  Agent／Profile 列表、共享记忆查询、工具列表、健康状态、运行信息十项基础操作。
  管理台所需的查询和运行控制也在核心范围内，不受“仅十项”限制。（US5-A1、US5-A4）
- **FR-032**：HTTP 成功与失败必须有一致、可理解的表达，可区分输入错误、资源不存在、
  模型不可用、执行失败和超时；消息最大 32KB，历史单次返回最多 100 条，
  已保存的其余历史可继续查询。（US5-A1、US5-A2）
- **FR-033**：单次交互请求等待结果的时限为 60 秒，达到时限返回超时而不是成功。
  对该手动任务停止发起新的模型、工具及通知调用，包括自动重试；不得后台续跑剩余步骤。
  已发出的外部请求不保证可撤销，迟到结果只更新该步骤记录，不重启循环；
  已完成或结果不确定的动作如实呈现，保留已有进度，不宣称全部取消成功。
  超时响应必须提供可查询的执行标识，并提示重试前先核对记录。（US5-A2）
- **FR-034**：作者必须能通过 Agent 配置声明定时时间、时区与任务内容；
  服务常驻时自动触发，使用与人工任务相同的模型、工具、记忆和记录规则。（US5-A3、IT-01 至 IT-03）
- **FR-035**：同一定时任务不得重叠执行，重叠触发须跳过且可观察；
  普通模型／工具失败不影响后续调度；会话／审计保存故障按 FR-040 暂停执行。
  不自动补跑停机或故障暂停期间错过的触发。（US5-A3、US5-A5、US5-A7）
- **FR-036**：运营者必须能查看定时任务的启停状态、下次触发、上次结果和执行历史，
  启用／停用及立即执行；停用任务允许手动执行，手动执行同样不得重叠，
  且不得绕过 FR-040 的工作区执行暂停。（US5-A4、US5-A7）
- **FR-037**：首版管理台必须展示真实 Agent、会话、共享记忆和定时任务数据，
  支持 Agent 手动触发和定时运行控制；不提供 Agent 定义增删改、运行配置热更新或 cron 编辑。
  控制失败须显示原因，不能提前显示成功。（US5-A4、US5-A8）
- **FR-038**：US-1 至 US-4 可用结构化日志证明调用链；
  US-5 必须持久化模型及工具成功、失败、权限拒绝的关联记录，
  重启后仍可核查，不得将日志冒充已落库审计；保存失败必须触发 FR-040 的异常处理，
  不得继续产生无法留痕的新任务。（US5-A5 至 US5-A7）
- **FR-039**：执行记录必须保留实际模型来源、工具名称、必要的脱敏参数与结果、耗时、
  可取得的用量及失败原因；未知值如实标明。（US5-A6）
- **FR-040**：当动作已发生而会话／审计保存失败时，整体显示“部分完成／记录保存异常”，
  分别说明已发生动作、无法确认的动作和未保存记录；通过响应、管理台运行状态及可用日志告警。
  停止当前任务后续动作，该工作区暂停新的人工、定时执行及新动作调度，
  返回明确的暂停原因，不隐式排队；在途动作不保证可撤销，其已知或未知结果须如实说明。
  保留仍可用的查询，查询失败不得返回假空数据。维护者修复存储、核对缺失记录并明确确认，
  且存储可写检查通过后才恢复执行；仅自动恢复可写或重启不能绕过该确认。
  不自动重放已发生动作、不补跑故障期间遗漏触发；历史记录无法补齐时保留缺失说明，
  不伪造完整记录。恢复的具体操作入口与故障状态保存方式由 plan 定义。（US5-A7）
- **FR-041**：必须提供可照做的启动、配置、CLI、HTTP 与管理台操作说明，
  明确外部服务前提、失败排查方式和当前能力边界。（US5-A1、US5-A4；SC-010）

### Key Entities *(include if feature involves data)*

- **工作区**：一套 Agent 定义、共享长期记忆、凭证引用与运行记录的管理范围；
  切换工作区不应继续访问上一工作区的状态。
- **Agent 定义／Profile**：业务用途、任务指令、模型选择、可用工具、通知和定时配置；
  `AGENT.md` 是定义源；Profile 是由其头部配置区派生的运行配置，不是另一份独立业务定义。
- **模型服务**：可被选择的供应商、模型及连接配置；真实凭证不作为普通查询内容。
- **任务执行**：某次人工或定时触发，关联 Agent、入口身份、会话、开始结束时间和执行结果；
  超时执行不再发起后续步骤，但可能包含已完成或结果不确定的外部动作，须能按执行标识查询。
  动作结果与保存状态分别表达；动作已发生但记录未保存时显示部分完成／记录保存异常。
  工作区执行状态区分可运行与记录故障暂停，后者需维护者确认恢复。
- **Session／会话**：某个入口、用户、Agent 下的一段连续对话，具有独立标识、历史和归档状态。
- **消息与工具结果**：用户输入、模型响应、工具请求及对应结果，能够还原一次任务处理过程。
- **长期记忆条目**：工作区共享的偏好或事实，区分核心与归档；不是完整对话历史的副本。
- **工具及允许规则**：工具的用途、输入要求、结果、可用范围及资源限制。
- **通知目标**：维护者配置的接收位置及凭证引用；任务使用目标名称而非获取其秘密值。
- **定时任务与执行历史**：时间、时区、任务内容、启停状态和历次结果；运行状态不取代文件定义。
- **执行审计**：模型或工具尝试的关联信息、脱敏参数、结果、耗时及用量，供故障定位和验收检查。

## Success Criteria *(mandatory)*

### Measurable Outcomes

以下均为待实现、待验证的目标；三项验收决策已澄清，不表示业务功能已经实现或通过测试。

- **SC-001**：五个故事各有至少一个成功演示和一个失败／边界演示，
  都可根据明确输入和可观察结果重复检查；五项全部通过才满足核心范围。
- **SC-002**：至少两家指定模型服务完成真实请求响应和工具任务；
  所有错误配置用例均给出明确失败，不发生供应商串用或自动故障切换。（FR-003 至 FR-005）
- **SC-003**：九项基线工具各通过允许用例和适用的失败／拒绝用例；
  越界用例中被拒绝的副作用为零，正常通知场景的重复发送为零。（FR-019 至 FR-028）
- **SC-004**：会话身份矩阵中改变入口、用户、Agent 任一项均不自动串入原历史；
  一条成功保存的长期偏好在新会话、另一个 Agent 和重启后仍可读取；
  多个并发写入中已确认保存的信息不因并发覆盖而丢失。三种记忆模式均须验证核心原文完整保留、
  未触发保存的信息不进入长期记忆；基础模式验证原文和关键词匹配，增强模式通过 US3-A6 的
  同义查询命中与无关查询不命中，返回事实与明确保存内容相符。（FR-010 至 FR-018）
- **SC-005**：三个整合场景各完成一次定时与一次手动触发，共至少六次成功端到端演示；
  每次能核对数据来源、处理结果、目标接收及执行记录，并各展示一种失败情形。
- **SC-006**：存储可正常写入的核心验收样本中，模型成功／失败、工具成功／失败／拒绝的
  持久化记录覆盖率为 100%；重启后已保存记录保留率为 100%，检查输出中不含用于测试的
  真实秘密值。模拟“通知已接收而记录保存失败”时，结果必须显示部分完成及记录异常，
  后续新增执行及重复通知次数为零；维护者确认恢复后只执行新任务，缺失记录仍如实说明。
  不把故障样本中的缺失记录算作保存成功。（FR-038 至 FR-040）
- **SC-007**：单机同时配置至少 10 个可用 Agent、保持至少 100 个并发会话，
  连续验证 4 小时，无对话串用、已确认写入丢失或任务重叠执行。
- **SC-008**：在上述受控负载下，创建会话的 P99 完成时间不超过 200ms；
  单次任务系统自身处理的额外耗时不超过 50ms。
  模型与外部工具的等待时间单独记录并扣除；测试设备、任务样本和测量口径随验收报告给出。
- **SC-009**：运营者无需手动查存储文件，即可在管理台完成 Agent／会话／记忆／定时状态查看、
  手动运行和启停控制；每项操作的显示状态均与执行结果一致，控制失败不会显示为成功。
- **SC-010**：具备所需运行环境和测试凭证的新使用者，按文档在 30 分钟内完成单机启动、
  一次任务请求和一次结果查询；文档明确区分已实现、需配置和未支持能力。
- **SC-011**：输入错误、资源不存在、工具拒绝、模型故障、循环上限和请求超时等失败用例
  均得到可识别结果；交互等待不会超过约定的 60 秒仍被无提示挂起。
  手动任务达到时限后新发起的模型、工具、通知调用及重试次数为零；
  模拟迟到响应不得重新启动任务，已发出动作的结果可按执行标识核查，不得显示为全部撤销。
  记录故障暂停期间，人工和定时触发均不执行且原因可见；仅修复存储或重启服务不会自动恢复，
  维护者确认且可写检查通过后，后续新任务可运行，旧动作和遗漏触发均不自动重放。

## Assumptions

### 已确认约束与采用的默认值

- **AS-01**：按用户本轮“已经确认的项目宪章”指示使用宪章 v1.0.0。
  宪章效力状态已依此确认同步；首次批准日期未登记，不补造日期，
  不视为需要重新询问已经确认的八项决定。
- **AS-02**：当前采用单机、受信任本地／内网环境，不实现登录、SSO、角色授权或多租户。
  入口提供稳定的用户标识用于区分会话，但不将该标识当作已验证身份；
  同工作区长期记忆为共享信息，不能放入要求用户隔离的秘密。
- **AS-03**：运行配置由文件维护、重启生效，正文按次读取；管理台仅查看与运行控制。
  Agent 定义以各自 `AGENT.md` 为准；Provider 连接信息与工具白名单以维护者的运行配置文件
  为准；通知目标由 Agent 的 `notify_channels` 声明。秘密值由环境变量或受控本地配置注入，
  不放正文。数据库保存会话、审计、调度运行状态等，不作为这些定义的另一可编辑权威源。
  调度启停状态与文件中的时间、时区、任务内容分别管理；重启恢复状态不能替换文件定义。
  本项依据宪章 III／当前阶段约束及技术方案 §3.2、§6.7–6.8、§11.1 补全，不重新询问。
  工作区和数据库位置沿用宪章确认规则；配置文件布局、字段和覆盖细节交给 plan。
- **AS-04**：一次性调用默认从空对话开始，不隐式续接已有会话，
  但仍产生可查询的执行／对话记录；持续对话必须明确使用会话标识。
  归档不删除已保存记录，不在本阶段增加自动过期删除。
- **AS-05**：同一会话正在处理任务时，额外请求明确返回忙碌，不排入隐式队列。
  同一定时任务的重叠触发跳过；不同任务共享同一活跃会话时同样遵守忙碌规则。
- **AS-06**：沿用需求文档的有限重试方向，对安全可重复、明确可重试的失败最多重试 3 次，
  即首次调用外至多 3 次重试；不自动重放结果不确定的副作用操作。
  具体间隔和可重试错误映射由 plan 定义，并用验证用例证明。
- **AS-07**：默认循环 10 轮、近期历史 20 轮、归档注入预算 4000 字符、
  消息 32KB、单次历史返回 100 条、交互等待 60 秒，来自现有需求与方案。
  历史“轮”必须覆盖完整的用户任务及其模型／工具消息，不以任意单条截断。
- **AS-08**：按技术方案 §5 的明确范围提供三种记忆方式；默认无需额外服务。
  本阶段不承诺自动跨方式迁移既有记忆；切换前须说明可见数据范围变化，
  原有已保存内容不得被切换操作删除。增强模式按已确认的 NC-01 执行，
  该模式不改变工作区共享范围，也不放宽核心原文完整保留的要求。
- **AS-09**：维护者提供至少两个模型服务的有效测试配置、可核对的通知目标，
  以及场景所需的数据源／可信脚本。外部额度、网络和服务可用性是联调前提；
  前提缺失须报告未验证，不能用替身通过冒充真实连通。
- **AS-10**：每个故事的验证可以先使用临时工作区和可控输入；
  整合演示与性能验证单独记录条件。课程“4 周／12 小时”不作为本功能的交付承诺。
- **AS-11**：需求 §8 与 §13 的延迟边界分别有“不超过”和“严格小于”表述，

- **AS-12**：技术方案的 Agent 列表与基础 Profile 列表在本规格统一为“查询已定义 Agent”，

### 验收决策与澄清状态

**NC-01 — 增强记忆模式的行为边界（已确认 A，2026-11-12）**

**NC-02 — 请求超时后的任务与通知（已确认 A，2026-11-12）**

**NC-03 — 动作成功但记录保存失败（已确认 A，2026-11-12）**
