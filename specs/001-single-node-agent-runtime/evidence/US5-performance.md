## 固定负载与环境

负载源为 `oryxos-boot/src/test/resources/performance/load-profile.json`。
10 个可用 Agent，100 个独立 HTTP 用户与活跃会话，每 Agent 分配 10 个客户端，每客户端最多一个在途任务，
收到结果且执行完全收尾后立即发起下一任务，无人为思考间隔。每轮按模型→HTTP 工具→模型串行执行；
三段固定外部等待分别为 10 秒、5 秒、10 秒。每 60 秒在负载下创建并归档一个探测会话。
10 个独立预热会话各执行两轮并归档，然后创建 100 个负载会话，进入连续 14400 秒稳态窗口，最后排空在途任务。

本机为 Mac16,1，10 核，16 GiB RAM，APFS；已有 JDK 21.0.13+9 只读复用。
所有构建、缓存、临时工作区和测试数据均在个人 checkout 的 `tools/dev` 隔离范围。
生产 Spring Boot 服务、负载客户端和可控端点位于同一个测试 JVM；不是发行 JAR 独立进程性能结论。
实际端口、JVM 参数、CPU、堆、GC、磁盘空间、run ID 与采样时刻保留在原始证据中。

## 计时与通过条件

单调时钟记录最外层测试 Servlet Filter 进入至同步完成或异步 onComplete，包含 MVC 和响应序列化。
另保留 HTTP 客户端往返耗时。内部耗时仅减去三段 `min(实测 sleep, 配置 sleep)`；
外部端点序列化、传输、sleep 超时、框架、排队、锁、数据库提交及完整审计均不扣除。
预热样本独立标记，不混入稳态分布。100 个正式会话的创建及负载下创建探测均计入创建指标。

会话创建 P99 必须 ≤200ms；**所有稳态任务内部最大值必须 ≤50ms**，报告 P50/P95/P99 和最大值，不能以 P99 替代最大值。
完整 4 小时及无任务失败、串话、重叠、丢失已确认写入和完整审计同时满足才通过。
超出耗时阈值不会提前终止观测；磁盘不足、运行异常或未排空会失败并保留事实。

确定性 token 包含运行、阶段、客户端、Agent 和轮次。端点核对当前用户历史、Agent 指令、工具回填及单会话在途状态。
结束后逐条核对真实 SQLite：每个成功执行对应 2 条模型记录、1 条工具记录、4 条消息，身份/token、消息序号、
工具调用配对、执行区间、100 个活跃会话、已确认写入存在性，以及 integrity_check/foreign_key_check。
每条任务、创建请求和外部等待均写 JSONL，不仅保留聚合统计。

## 测试先行及发现

1. 先登记本地夹具测试；缺失负载文件时按预期红灯，日志 `batch9-red.log`。
2. 第一轮 100 会话短程在首次并发执行时停滞。线程转储显示 Java 21 虚拟线程阻塞于
   SessionManager 的 intrinsic monitor，持锁线程在 Hikari 连接归还交接中无法让出载体。
   保留 `batch9-smoke-threads.json`、`batch9-smoke-platform-threads.txt` 及该次工作区，结束停滞测试。
   SessionManager 改用 ReentrantLock，原 acquire/archive/close 互斥边界和身份/占用语义不变。
3. 第二轮揭示 HTTP 的固定 64 在途上限：100 客户端中出现 OVERLOADED，记录 108 次失败；
   已确认执行的 SQLite 核对通过。生产 HTTP 有界容量提升到 128，保留过载拒绝行为，支持目标 100 会话及响应收尾余量。
4. 第三轮本地夹具 4 项测试通过，run ID `2ec98157-3833-48c3-81c7-ff6d32345d5f`。
   短程使用 5ms/3ms/5ms 和 3 秒窗口，始终标记 `SMOKE_ONLY_NOT_T101`，不是四小时证据。

原始日志、转储和工作区位于 `.oryxos-dev/evidence/`，包含纯测试 token 和回环地址，无真实凭证。
短程验证只用于夹具与并发修复，不替代以下完整四小时结果。
