## 修复与边界

- `RuntimeTiming` 采用单调时钟，默认关闭，只记录阶段名及起止时间，不记录模型内容或密钥。HTTP 与 Agent 工作线程显式传递观察器，保留排队、会话锁、历史、数据库、提交、审计和模型/工具调用的嵌套区间。
- 序号查询改为数据库 MAX，历史只读取最近指定数量的完整回合及当前回合，结束回合只校验本回合。V007 新增索引；V001–V006 不改，不删除历史，不用内存数据代替 SQLite。
- 会话接收、归档及释放按 Session ID 串行，空闲锁移除；独立会话不再因一个会话的存储阻塞而等待全局锁。
- 单写协调器只合并已经排队的最多 128 条写入，不引入收集等待。最多 257 条未完成记录（原来一个执行者加 256 等待者的容量）；等待仍有剩余预算。事务从创建到关闭均在同一写线程内，只有完整提交并释放资源后才确认成功；组内任何失败回滚整组、先暂停再通知调用方。
- 高频 Session/Execution/Audit 写入使用 JPA 所属连接上的参数化 SQL，保持正式实现及同一事务、外键、终态和身份校验；序列化及脱敏在入队前完成，仍计入请求总耗时。SQLite 保持 WAL、synchronous=FULL，没有异步确认或抽样审计。
- 模型适配器复用每个 Provider 所属的 HTTP 连接与序列化器。请求工厂及剩余超时仍逐次创建；并发短请求超时不会关闭其他请求的连接。注册表关闭时释放连接。

Spring 6.2.19 的逐请求超时处理覆盖响应等待及响应体关闭，源码依据为 [JdkClientHttpRequest](https://raw.githubusercontent.com/spring-projects/spring-framework/v6.2.19/spring-web/src/main/java/org/springframework/http/client/JdkClientHttpRequest.java)；转换器初始化及 builder 复制依据为 [DefaultRestClientBuilder](https://raw.githubusercontent.com/spring-projects/spring-framework/v6.2.19/spring-web/src/main/java/org/springframework/web/client/DefaultRestClientBuilder.java)。本地并发、断连、截止与协议测试仍是本项目行为验证依据。

## 计时口径

原 `internalNanos = serverNanos - externalDeductedNanos` 原样保留，便于与失败基线比较。仅扣每段 `min(实际外部 sleep, 配置 sleep)`；超过配置的 sleep、队列、数据库与审计都不扣除。

新增 `ingressIncludedInternalNanos = max(serverNanos, clientNanos) - externalDeductedNanos` 作为更保守的上界门槛，覆盖 Servlet 入口以外可能存在的排队。它也包含客户端/回环传输开销，不能称作精确的纯服务端时间。通过要求两个最大值均不超过 50ms，创建 P99 仍须不超过 200ms。保留全部样本，嵌套分段不能直接相加。
