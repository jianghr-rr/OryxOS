# Feature Specification: 云端天气与通知 Agent 配置及自动交付

**Feature Branch**: `003-cloud-weather-notify-agents`  
**Created**: 2026-11-19  
**Status**: Clarified (Ready for Plan)  
**Input**: User description: "解决腾讯云部署后管理台缺少天气查询与飞书通知 Agent、且云端运行配置模板与当前运行时要求不一致导致模型服务与外网访问不可用的问题；以 Spec Kit 流程完成云端 Agent 模板、运行配置修正与发布同步能力建设。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 云端工作区运行配置与模型/外网访问就绪 (Priority: P1)

运维人员完成腾讯云部署后，云端工作区的模型服务配置与受控外网访问白名单符合当前运行时校验规则，且全部敏感凭证仅通过服务器受限权限的本地密钥文件解析，从而确保云端服务启动时模型服务与外网工具均可正常初始化，而不是在配置校验阶段即变为不可用。

**Why this priority**: 若云端工作区基础配置与运行时要求不匹配或外网白名单为空，即便添加了天气或通知 Agent，也会在启动校验或工具执行阶段直接报错阻断，是后续一切业务 Agent 可用的前置条件。

**Independent Test**: 在已注入有效云端密钥的工作区中使用修正后的云端运行配置模板启动服务，打开 `/admin/#agents` 与运行状态接口，验证模型服务可用且仅对已声明的天气数据源与飞书通知域名放行出站请求。

**Acceptance Scenarios**:

1. **Given** 服务器受限权限的本地密钥文件已包含有效的模型与通知凭证，且已启用修正后的云端运行配置，**When** 服务启动并打开 `/admin/#agents`，**Then** 所绑定的模型服务正常加载且不出现配置缺失或服务不可用错误。
2. **Given** Agent 在执行过程中发起天气查询或飞书通知请求，**When** 目标地址命中已声明的受控外网白名单，**Then** 请求被允许发出；当请求目标不在白名单内时，系统在发起网络请求前予以拒绝且不产生外发副作用。
3. **Given** 本特性涉及的所有文档、配置模板与部署脚本已进入仓库，**When** 对仓库受跟踪文件执行敏感信息扫描，**Then** 任何文件中均不包含真实 API Key、Webhook URL、服务器主机信息或访问令牌。

---

### User Story 2 - 云端天气查询与飞书通知 Agent 上架与手动验证 (Priority: P1)

运维人员部署完成后打开云端管理台 `/admin/#agents`，即可直接看到两个可用业务 Agent——`weather`（天气查询 + 飞书播报）和 `feishu-notify`（独立飞书通知）——而初始占位且不可用的 `default` Agent 已被清理移除（若有运维自建的其它自定义 Agent 则保持不变）；运维人员可在页面直接触发手动运行，获取真实天气摘要并向指定飞书群发送带明确回执确认的通知消息，同时落库完整脱敏的执行审计记录。

**Why this priority**: 解决用户在腾讯云部署后页面缺少天气与通知 Agent、仅显示不可用 `default` 而无法开箱验证真实业务链路的核心痛点。

**Independent Test**: 部署更新并重启云端服务后，访问 `/admin/#agents` 确认页面仅展示 `weather` 与 `feishu-notify`（以及如有自建的其他 Agent）且均处于可用状态、`default` 已被清理；通过管理台分别触发手动任务，核对返回摘要、飞书群实际收信及执行记录详情。

**Acceptance Scenarios**:

1. **Given** 新版本及云端配置模板已部署至服务器并完成服务重启，**When** 用户访问 `/admin/#agents`，**Then** `weather` 与 `feishu-notify` 均展示为可用状态并正确呈现其模型绑定、允许工具列表与通知目标元数据，且不可用的 `default` Agent 不再出现。
2. **Given** 用户在管理台手动运行 `weather` Agent 并发起某城市天气查询及通知指令，**When** 本次执行完成，**Then** Agent 从真实天气数据源获取结果、生成简明中文摘要并通过飞书通知通道发送一次消息（经明确投递确认），且完整脱敏记录落库可查。
3. **Given** 用户在管理台手动运行 `feishu-notify` Agent 并指定通知内容，**When** 本次执行完成，**Then** 飞书测试群收到对应消息且执行历史中记录明确的确认状态，无明文密钥泄露。

---

### User Story 3 - 自动发布托管同步与无损升级 (Priority: P2)

后续每次通过自动化发布流程升级云端版本时，发布流水线自动将仓库中的托管运行配置与托管 Agent 定义（`weather`、`feishu-notify`）同步到云端工作区，并清理残留的占位 `default` Agent，同时完整保留云端已产生的数据库会话、共享记忆、输出文件、本地密钥及非托管自定义 Agent；同时两个托管 Agent 均不配置自动定时推送（cron），仅支持按需手动触发，避免上线或升级时误发无预期群消息。

**Why this priority**: 已初始化过的云主机不会再重新执行首次初始化流程，若发布链路不解决已有工作区的自动托管同步问题，修复后的配置无法自动送达已上线服务器；同时关闭自动定时任务可确保通知完全受控。

**Independent Test**: 在已存在旧版无效运行配置、`default` Agent、历史会话/记忆数据、本地密钥及非托管自建 Agent 的工作区上执行一次发布同步流程，验证旧配置被修复、`default` 被清理、`weather` 与 `feishu-notify` 同步就绪、所有历史数据与非托管内容完整保留，且定时任务列表中无天气或通知自动调度。

**Acceptance Scenarios**:

1. **Given** 云主机上已初始化过工作区且存在旧版无效运行配置、`default` Agent、历史会话/记忆数据以及运维自建的非托管 Agent，**When** 执行自动化发布流程，**Then** 托管运行配置与 `weather`、`feishu-notify` 完成同步更新且 `default` 被清理，同时原有数据库、长期记忆、输出目录、`0600` 本地密钥文件及非托管自建 Agent 保持完整未受损。
2. **Given** 本次托管同步的版本已重启上线，**When** 用户查看管理台运行状态与定时任务列表，**Then** 服务以新配置完成健康检查且日志呈现各托管 Agent 可用状态，`weather` 与 `feishu-notify` 均未注册自动定时任务，所有执行仅由管理台、接口或命令行手动触发。

---

### Edge Cases

- **已有服务器残留旧版无效运行配置与占位 `default` Agent**：若此前已完成首次初始化并落盘了旧版模板生成的无效运行配置与不可用 `default` 目录，仅靠“文件不存在时才初始化”的机制无法修复线上环境；发布流程每次执行托管同步时必须覆盖托管运行配置与托管 Agent 目录，并清理残留 `default` 目录。
- **密钥占位符命名不一致或缺失**：当部署注入的本地密钥文件键名与 Agent 通知配置或模型配置引用的占位符不一致（或某密钥未配置）时，受影响 Agent 应优雅降级为不可用状态并在诊断信息中脱敏提示，不得导致整个运行内核崩溃或泄露密钥值。
- **天气数据源或飞书通知外部调用失败/超时**：当天气服务不可达、返回缺字段或飞书返回非确认结果及网络超时状态时，系统必须据实记录失败或未确认状态，不得编造天气数据或自动重试具有外发副作用的通知。
- **版本回滚时的配置一致性**：当新版本发布失败触发自动或手动回滚至上一可用版本时，若上一版本附带历史托管配置快照，回滚流程需同步还原对应的托管配置，避免出现程序包回退而新配置不兼容的错配。
- **同步与重启过程中的文件权限与工作区锁冲突**：同步服务器工作区文件后，若文件属主或权限不正确会导致非特权运行用户无权读取或触发权限校验拒绝；同时重启切换必须等待旧实例释放工作区互斥锁。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (云端运行配置有效性)**: 云端工作区运行配置模板 MUST 符合当前运行时的校验规范，确保已配置的外部模型服务在服务启动后正常加载为可用状态，且仅通过本地密钥占位符引用凭证。
- **FR-002 (受控外网访问白名单)**: 云端工作区运行配置模板 MUST 显式声明天气数据源与飞书通知服务所需的最小出站目标白名单，同时保持对未声明外部主机的默认拒绝边界。
- **FR-003 (密钥命名一致性与零入库)**: 云端 Agent 定义模板、运行配置模板与自动化密钥渲染流程 MUST 使用一致的凭证占位符命名约定；仓库内所有受跟踪文件、运行日志、管理台回显与持久化审计记录中 MUST NOT 出现任何明文密钥或真实 Webhook 地址。
- **FR-004 (云端上架 Agent 集合与 `default` 清理)**: 云端部署 MUST 在工作区中提供 `weather`（天气查询 + 飞书播报）与 `feishu-notify`（独立飞书通知）两个可用托管 Agent，并在同步时清理初始化生成的占位 `default` Agent 目录（按已确认策略 `Q1=B` 执行）。
- **FR-005 (天气与通知业务行为)**: `weather` Agent MUST 根据请求查询真实天气数据、整理为结构清晰的中文天气摘要，并通过已声明的飞书通知目标发送消息；`feishu-notify` Agent MUST 支持按请求直接向飞书目标发送通知消息；两者均 MUST 仅在收到通知接收端的明确业务确认回执后报告发送成功，遇到数据缺失或通知异常时 MUST 据实说明并禁止编造数据或自动重复发送通知。
- **FR-006 (纯手动触发与零定时调度)**: `weather` 与 `feishu-notify` 均 MUST NOT 配置自动定时推送任务（cron），全部执行仅支持通过管理台、REST 接口或命令行手动触发，避免无预期的自动群发通知（按已确认策略 `Q2=C` 执行）。
- **FR-007 (每次发布托管同步与非托管保留)**: 每次自动化发布交付流程 MUST 自动将仓库中的托管运行配置与托管 Agent 定义（`weather`、`feishu-notify`）同步至云端工作区并移除 `default` 占位目录，同时 MUST 严格保留云端持久化数据库、共享记忆、输出文件、运行时元数据、`0600` 本地密钥文件以及任何非托管自定义 Agent 目录（按已确认策略 `Q3=A` 执行）。
- **FR-008 (重启生效、最小权限与回滚一致)**: 云端工作区配置文件与 Agent 定义同步落盘后，MUST 保持专用运行用户的最小必要读写权限（本地密钥文件保持 `0600`），并通过服务受控重启与健康检查使配置变更立即生效；当发布触发回滚且上一版本包含配置快照时，回滚流程 MUST 一并恢复对应配置快照。

### Key Entities

- **云端运行配置 (Cloud Runtime Configuration)**: 定义云端工作区时区、模型服务绑定（通过密钥占位符）、记忆后端及文件/命令/网络工具安全边界的工作区级配置。
- **托管 Agent 定义 (Managed Agent Definition)**: 随版本模板交付的独立目录化 Agent 声明（本特性包含 `weather` 与 `feishu-notify`），包含所属模型绑定、允许使用的工具集、通知目标契约、空定时任务声明与行为指令正文。
- **云端受控密钥 (Cloud Secret Store)**: 仅保存在服务器本地受限权限文件中的敏感凭证集合，由自动化部署安全渲染或运维本地维护，供运行配置与 Agent 通过占位符名称引用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001 (Agent 开箱可用率)**: 部署与服务重启完成后，`weather` 与 `feishu-notify` 在管理台中的可用率达到 `100%`（零配置校验报错），且不再出现不可用的 `default` Agent。
- **SC-002 (真实链路端到端验证)**: 在管理台手动触发一次 `feishu-notify` 通知测试与一次 `weather` 天气播报任务，均在 `60 秒` 内完成飞书群成功送达确认与完整审计记录落库。
- **SC-003 (敏感凭证零泄露)**: 对仓库全量受跟踪文件、服务器运行日志及管理台接口返回执行扫描，明文 API Key 与 Webhook 地址命中数为 `0`。
- **SC-004 (升级平滑与数据无损)**: 对已存在旧配置、历史会话、长期记忆、本地密钥及非托管自定义 Agent 的服务器执行托管同步与发布更新时，非托管数据保留率为 `100%`，托管配置在单次发布周期内完成生效。
- **SC-005 (外网边界有效性)**: 未列入白名单的外部网络目标访问在发起真实网络传输前被拦截的比例为 `100%`。

## Assumptions

- 腾讯云主机已完成基础环境初始化（Java 21、`systemd` 守护进程、非特权运行用户与目录权限基线，见 `002-tencent-cloud-deployment`）。
- GitHub 仓库 Secrets 中已配置模型 API Key（`DEEPSEEK_API_KEY`）与飞书通知地址（`FEISHU_WEBHOOK_URL`），且云主机网络环境可正常访问 DeepSeek 接口、Open-Meteo 天气接口与飞书 Webhook 接口。
- 遵循项目宪章 v1.0.0：管理台仅承担查看与运行控制职责，Agent 定义与运行配置仍通过文件维护并在服务重启后加载。
- 仓库内用于本地调试的工作区目录仍保持本地忽略状态，不直接纳入 Git 版本控制。
